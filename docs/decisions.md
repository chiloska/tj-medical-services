# Decisions

## ADR-1: WhatsApp notifications as plain Vercel Functions next to the static site
- **Status:** Accepted
- **Date:** 2026-10-20
- **Context:** The handoff spec assumed Next.js API routes, but the site is static HTML generated by `src/build.py`.
- **Decision:** Root `api/*.ts` Vercel Functions (Node runtime, Web `Request`/`Response` handlers exporting `POST`). Shared code in `lib/notifications/`. npm/TypeScript only for these; tests with vitest. Twilio SDK for sending; Upstash Redis through its REST API (no `@upstash/redis` dependency) for idempotency, with in-memory fallback.
- **Alternatives considered:** Migrating to Next.js (too heavy for a static site); Python functions (spec and Twilio examples are TS).
- **Consequences:** The repo now has two toolchains (Python for the site, Node for functions). The package must stay CommonJS with extensionless imports. Deploy compatibility is unverified until the first preview.

## ADR-2: Clinic contact data generated for TypeScript from `src/data.py`
- **Status:** Accepted
- **Date:** 2026-10-20
- **Context:** WhatsApp messages need the clinic addresses, which already live in `src/data.py`.
- **Decision:** `src/build.py` writes `lib/notifications/clinic.generated.ts`. The edit-guard hook blocks hand edits to `*.generated.ts`.
- **Consequences:** Change contact data in `data.py` and rebuild. Template text itself (phone number, shuttle hours) is fixed by Twilio/Meta approval and is not generated.

## ADR-3: GitHub Issues and milestones as the agile backlog
- **Status:** Accepted
- **Date:** 2026-10-20
- **Context:** The user asked for agile tooling for a small project.
- **Decision:** Stories are GitHub issues with type, `size:S|M|L` and `priority:*` labels; one-week sprints are milestones named `Sprint N`; skills in `.claude/skills/` drive the cycle using the `gh` CLI (no GitHub MCP).
- **Consequences:** The repo is public, so issues must not contain real patient data.
